# Dual-V100 IQ3_S: selected v0.1.41 changes

## Configuration

Date: 2026-10-08. Two Tesla V100-PCIE-16GB cards, compute capability 7.0,
80 SMs per card, 175 W power limits, PCIe Gen3 x4 and x16.
CPU: Ryzen 5 3600, six cores and 12 threads. RAM: 94 GiB.
Driver: 580.178.04. Compiler: CUDA 12.8.93 and GCC 13.3, Release, `sm_70`.
Model: Qwen3.8-Flash-Next IQ3_S native GGUF shards, with the expert arena
and MTP weights already on local storage.

The baseline source is fork main `1cb28c34`. The candidate is a selected source
port from upstream v0.1.41 `fb58e0db`. The existing benchmark-only branch does
not change engine source. Each arm uses a separate built engine.
Binary SHA-256 values are in the raw records. Their `harness_checkout_commit`
field identifies the checkout that ran the harness, not the built source.
The candidate records identify the source base and the uncommitted port state.

Both arms use two GPUs, layer boundary 16, context 524,288, INT8 KV,
YARN scale 2, MTP window 8, speculative minimum probability 0.70,
expert cache auto, prefill auto, VRAM reserve 750 MiB,
`STRATA_EXPERT_PAIR=1`, and `STRATA_SPLIT_RING=192`.
CPU assistance is explicitly `STRATA_PREFILL_CPU_SHARE=auto` in every arm.

## Method

Use `bench/run_v100_prefill.py`, direct GENI protocol with an empty embedding
file, seed 20261008, three repeats per length, temperature zero, and at most
128 output tokens. Prompt hashes match between the full-matrix arms.
Prompt and conversation caches are disabled. All measured rows report zero
reused prompt tokens. The engine reports conversation cache 0 and disk cache 0.

The existing harness checks Q2_0 settings. Use `--no-settings-strict` because
this IQ3_S configuration uses reserve 750, not 700. Its cache check also sees
the earlier duplicate conversation-cache argument, although the final argument
is zero and the engine reports zero. Neither mismatch is a measured cache hit.

Each engine starts from a separate process. The harness waits for a stable
starting temperature of at most 55 C and samples both cards once per second.
The sequence is baseline, Volta option, baseline return, accounted buffer,
conservative candidate, isolated CPU-threshold arms, and selected profile.
This is an ablation sequence, not a randomized statistical experiment.

Decode tok/s is `1000 * generated / decode_ms`. The tables use the median of
three per-request rates. All baseline outputs have 128 tokens. Selected 2K
repeat 3 ends at EOS after 20 tokens; the other eight selected rows have 128.
Thus its 2K decode median includes a shorter row. Treat decode values as
observations, not fixed-output-length or exact-output speed claims.

## Selected profile

```sh
STRATA_PREFILL_CPU_SHARE=auto
STRATA_PREFILL_STREAM_MIN=3072
STRATA_EMB_REUSE_ACCOUNT=1
STRATA_SM70_TABLE=1
```

The first option already applies in the original service. The larger stream
threshold is an existing fork setting equivalent to upstream's optional
larger-chunk CPU assistance. It moves 2K prompts to staged CPU-assisted work;
it does not force 8K and 32K prompts into small chunks. The threshold is
exclusive. The buffer option reduces prompt loans. The master Volta option
selects the tested decode kernels. All new kernel options remain optional.
No private service configuration or installed engine is changed by this PR.

Use a private copy of the IQ3_S arena configuration. Keep credentials out of
published files. Build the baseline and candidate in separate build directories.
Do not run two engines at the same time. Set the paths below to those engines
and the private configuration.

```sh
python bench/run_v100_prefill.py --config "$PRIVATE_CONFIG" \
  --exe "$BASELINE_ENGINE" --arm-label baseline \
  --targets 2048,8192,32768 --repeats 3 --seed 20261008 --max-new 128 \
  --no-settings-strict --env STRATA_PREFILL_CPU_SHARE=auto \
  --out /tmp/v0141-baseline

python bench/run_v100_prefill.py --config "$PRIVATE_CONFIG" \
  --exe "$CANDIDATE_ENGINE" --arm-label selected \
  --targets 2048,8192,32768 --repeats 3 --seed 20261008 --max-new 128 \
  --no-settings-strict --env STRATA_PREFILL_CPU_SHARE=auto \
  --env STRATA_PREFILL_STREAM_MIN=3072 \
  --env STRATA_EMB_REUSE_ACCOUNT=1 --env STRATA_SM70_TABLE=1 \
  --out /tmp/v0141-selected
```

## Main comparison

All values are tokens per second.

| Prompt tokens | Baseline prefill | Selected prefill | Prefill change | Baseline decode | Selected decode |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 2,048 | 420.09 | 700.96 | +66.86% | 56.26 | 57.50 |
| 8,192 | 1005.30 | 1009.56 | +0.42% | 57.10 | 56.59 |
| 32,768 | 1645.83 | 1660.57 | +0.90% | 52.65 | 57.26 |

The main prefill result is +66.86% at 2K, or 4,875.1 to 2,921.7 ms median
prompt latency. The 8K and 32K changes are small and do not establish a stable
long-prompt improvement. The 32K decode observation is +8.76% against the first
baseline, but only +3.34% against the return baseline. Do not describe it as
an established 8.76% decode gain.

## Ablations and repeatability

Each cell is prefill / decode tok/s.

| Arm | 2K | 8K | 32K |
| --- | ---: | ---: | ---: |
| baseline | 420.09 / 56.26 | 1005.30 / 57.10 | 1645.83 / 52.65 |
| baseline-return | 419.95 / 54.90 | 1001.30 / 57.70 | 1651.30 / 55.41 |
| conservative | 419.77 / 58.88 | 998.31 / 53.99 | 1634.58 / 54.04 |
| volta | 419.92 / 59.39 | 1001.10 / 54.48 | 1639.01 / 54.57 |
| accounted | 421.62 / 59.66 | 1011.20 / 54.51 | 1645.83 / 54.74 |
| selected | 700.96 / 57.50 | 1009.56 / 56.59 | 1660.57 / 57.26 |

- `conservative`: ported source, neither Volta nor saved-buffer accounting
  enabled. The planner retains the previous byte accounting.
- `volta`: add `STRATA_SM70_TABLE=1` only.
- `accounted`: add Volta and saved-buffer accounting.
- `selected`: add the larger staged CPU threshold to those two options.

The isolated CPU-threshold comparison uses a different target set and therefore
a different prompt pool. Its own prompt hashes match across the two arms:
419.80 to 676.49 prefill tok/s (+61.15%), and 44.59 to 44.65 decode tok/s.
Do not mix its rows with the full matrix. Both arms use the same baseline
binary, so the prefill gain does not depend on a new decode kernel.

The same baseline binary differs in greedy output on eight of nine repeated
full-matrix prompts. Candidate output also differs. These runs do not prove
exact-output equivalence or model quality. The end-to-end cause is not assigned
by this experiment. Kernel tests below establish only their tested arithmetic.

## Memory and temperature

The startup planner keeps the auto chunk at 8,192 tokens in the baseline and
accounted candidate. With accounting enabled, the primary prompt budget drops
from 4.118657 to 4.041076 GiB. Stage 0 loans drop from 2,072 to 2,027 slots;
stage 1 loans drop from 1,832 to 1,791 slots. This is about 80 MiB less prompt
storage per stage. It leaves more expert-cache space during prefill.

The baseline request samples span 37–61 C. The return baseline spans 44–63 C.
The selected profile spans 43–63 C. Each reports zero thermal-slowdown samples.
Temperatures are not identical; no thermal slowdown was observed at the sample
rate. Raw per-row min/mean/max temperatures, power, and throttle masks remain
in the result files.

## Focused verification

These tests passed with `STRATA_SM70_TABLE=1`:

- `file_expert_source_test` and `expert_layout_test`.
- `mmvq_il_parity`, `gr_parity`, `native_multi_parity`, and `gr_multi_parity`.

`native_grouped_parity` passed with `STRATA_EXP_MODE=8`.
`fused_gr_bench 50 1 8` reported zero differing values for all 32 cases;
the fast path took about 7–10% less time in those kernel measurements.
The real-model `native_expert_bench` compared modes 0 and 8 on layers
0, 15, 16, and 47 with 16 groups and four tokens. It reported zero differing
values; complete-call times changed from 128.0 to 123.7, 132.2 to 118.5,
130.1 to 124.1, and 123.2 to 106.4 microseconds. These are kernel results,
not end-to-end speed claims. No full-suite result is claimed.

The mapped-source test initially failed because its fixture had experts.bin.
The resident-page check was moved to the genuine mapped-GGUF fixture and then
passed. Linux direct reads are excluded from page-cache profile selection.
The actual arena does not use this optional mapped-source optimization.

## Service restoration

The original user service was restored with its original installed engine,
CPU-share setting, layer split, cache configuration, and 524,288-token context.
The status endpoint returned HTTP 200 with one serving slot. A chat completed
with answer `READY`, finish reason `stop`, and 34 completion tokens. That
request reused 58 prompt tokens. No candidate engine was installed.
